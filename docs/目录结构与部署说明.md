# Legal Dev Assistant — 目录结构与部署说明

本文档概括仓库**逻辑目录结构**、模块依赖关系，以及**开发与生产部署**方式。细节与契约仍以 [README.md](../README.md)、[USAGE.md](./USAGE.md)、[contracts/openapi.yaml](../contracts/openapi.yaml) 为准。

---

## 1. 仓库根布局（逻辑树）

下列为**源码与交付相关**目录；不含 `node_modules/`、`backend/target/` 等可再生成路径。

```
competition/                          # 仓库根（建议整仓上传/克隆，勿只拷 backend）
├── README.md                         # 总入口：运行、超时、安全声明
├── contracts/
│   └── openapi.yaml                  # HTTP API 与 DTO 契约
├── docs/                             # 产品/验收/接口/使用说明
│   ├── USAGE.md                      # Web 案例 + curl
│   ├── golden-fixtures.md            # 场景与黄金样例矩阵
│   ├── mvp-acceptance.md             # 验收与不做清单
│   ├── api/                          # 接口叙事、NFR、错误语义
│   └── …
├── fixtures/                         # 黄金样例 + 演示正文（构建/测试依赖）
│   ├── stdlib/                       # 案号规则、文书管线、合规规则 YAML（打包进 JAR）
│   ├── case-number/
│   ├── document-extract/
│   └── compliance/
├── backend/                          # Spring Boot 3（Java 17+），Maven 工程
│   ├── pom.xml                       # 资源映射 ../fixtures/stdlib；package 时嵌 ../frontend
│   └── src/
│       ├── main/java/com/legaldev/mvp/
│       │   ├── LegalDevMvpApplication.java
│       │   ├── web/                  # REST：案号 / 文书 / 合规 + DTO + 全局异常
│       │   ├── caseno/               # 案号域服务
│       │   ├── extract/              # 文书抽取
│       │   ├── compliance/           # 合规扫描
│       │   ├── stdlib/               # 标准库装载
│       │   └── config/               # Jackson、超时、线程池等
│       ├── main/resources/
│       │   └── application.yml     # 端口 8080、stdlib 路径、处理超时等
│       └── test/java/…             # 黄金用例集成测试
└── frontend/                         # Vue 3 + Vite + Element Plus
    ├── package.json
    ├── vite.config.js                # 开发期 /api → localhost:8080 代理
    ├── index.html
    └── src/
        ├── main.js
        ├── App.vue
        ├── api/client.js             # axios baseURL: /api
        └── styles/shell.css
```

**构建产物（本地生成，勿提交到版本库）：**

- `frontend/node_modules/`、`frontend/dist/`
- `backend/target/`（含 `target/classes/static/`、`legal-dev-mvp-0.1.0-mvp.jar` 等）

## 2. 模块职责与依赖关系

| 路径 | 职责 |
|------|------|
| `backend/` | HTTP API；运行时从 classpath 加载 `fixtures/stdlib`；`mvn package` 时可选将前端 `dist` 拷入 `classpath:/static/`。 |
| `frontend/` | 三 Tab 演示 UI；生产与后端同源时请求 `/api/v1/...`。 |
| `fixtures/stdlib/` | 规则与管线真源，经 `pom.xml` `<resources>` 打进 JAR。 |
| `fixtures/{case-number,document-extract,compliance}/` | 黄金请求/期望与 `.txt` 样例，供测试与人工对照。 |
| `contracts/openapi.yaml` | 契约真源，与实现、文档对齐。 |
| `docs/` | 使用说明、验收、答辩材料，不参与运行时。 |

**完整性说明（部署上传范围）：**

- `backend/pom.xml` 使用 **`${project.basedir}/../fixtures/stdlib`** 与 **`${project.basedir}/../frontend`**。  
- 因此 **仅上传 `backend/` 文件夹不足以在干净环境完成 `mvn package`**；应保留**仓库根**下与上述相对路径一致的结构（至少包含 **`backend`、`fixtures`、`frontend`**），或改为只分发已打好的 **可执行 JAR**（stdlib 与可选静态页已在 JAR 内）。

## 3. 部署方式

### 3.1 开发：前后端双进程（热更新）

| 步骤 | 命令 / 说明 |
|------|-------------|
| 1 | `cd backend && mvn spring-boot:run` → 默认 **http://localhost:8080**，仅 API。 |
| 2 | `cd frontend && npm install && npm run dev` → 默认 **http://localhost:5173**，Vite 将 **`/api` 代理到 8080**。 |
| 3 | 浏览器打开 **5173** 使用界面；直接访问 **8080** 根路径若无已打包的 `static`，可能出现 **Whitelabel 404**（见 README 故障说明）。 |

### 3.2 生产：单进程（前端静态资源打进 JAR）

适合「一台机、一个 Java 进程」对外提供 **页面 + API**。

| 步骤 | 命令 / 说明 |
|------|-------------|
| 1 | 在 **`backend/`** 执行：`mvn clean package -DskipTests` |
| 2 | `prepare-package` 阶段：`../frontend` 下 **`npm ci`** + **`npm run build`**，将 **`frontend/dist`** 复制到 **`target/classes/static`**，再打进 **`target/legal-dev-mvp-0.1.0-mvp.jar`**。 |
| 3 | `java -jar target/legal-dev-mvp-0.1.0-mvp.jar` |
| 4 | 浏览器 **http://localhost:8080**（或与 `application.yml` 中 `server.port` 一致）；API 前缀 **`/api/v1/...`**。 |

**Maven 开关（与 `backend/pom.xml` 一致）：**

| 属性 | 含义 |
|------|------|
| `-Dfrontend.skip=true` | 跳过前端构建与静态拷贝（仅 API 的 JAR）。 |
| `-Dfrontend.skip.installnodenpm=false` | 在无本机 Node 的构建机上由插件下载 Node 再执行 `npm ci`；默认 **`true`** 表示使用 PATH 上的 `node`/`npm`。 |

**注意：** `mvn test` 生命周期**不包含** `prepare-package`，因此**不会**自动构建前端；`mvn spring-boot:run` 默认也**不会**执行嵌入前端的步骤。需要根路径有 UI 时，请先 **`mvn package`**（或直接用打好的 JAR）。

### 3.3 容器 / 云平台（通用做法）

1. 在镜像或构建流水线中安装 **JDK 17+**、**Maven**、**Node + npm**（若使用默认 `frontend.skip.installnodenpm=true`）。  
2. 将**完整仓库**（或至少 `backend` + `fixtures` + `frontend`）拷入构建上下文，`WORKDIR` 设为 `backend`。  
3. 执行 **`mvn clean package -DskipTests`**，将生成的 **`legal-dev-mvp-0.1.0-mvp.jar`** 复制到运行镜像，`ENTRYPOINT` 使用 **`java -jar`**。  
4. 暴露 **`server.port`**（默认 **8080**）；按需设置环境变量或挂载配置覆盖 `application.yml`（若你自行扩展）。

### 3.4 仅分发 JAR（不再携带源码）

在已信任环境完成 **`mvn package`** 后，单独分发 **`backend/target/legal-dev-mvp-0.1.0-mvp.jar`** 即可运行（stdlib 与 `-Dfrontend.skip=false` 时的静态 UI 已在包内）。**重新构建**仍需完整源码树或调整后的工程结构。

## 4. 网络与端口速查

| 组件 | 默认地址 | 说明 |
|------|-----------|------|
| Spring Boot | `http://localhost:8080` | `application.yml` → `server.port` |
| Vite 开发服务器 | `http://localhost:5173` | `vite.config.js` → `server.port` / `proxy['/api']` |
| API 前缀 | `/api/v1/...` | 与 OpenAPI `paths` 一致 |
