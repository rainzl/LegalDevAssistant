## 一、产品与功能背景

### 1.1 一句话

面向法律软件与合规相关研发的**离线最小能力集**：在**不依赖运行时云端大模型与业务数据上公网**的前提下，完成**案号格式校验**、**民事判决书单条结构化抽取**（固定管线 `civil-judgment-v1`）与**本地合规规则扫描**，输出可追溯的规则引用与结构化 JSON，便于竞赛评审、内训与集成调试。

### 1.2 要解决什么问题

法务/合规类系统在开发与联调阶段，往往需要反复校验案号形态、从裁判文书中稳定抽取关键字段、并对粘贴的文本或代码片段做**确定性**的敏感模式提示。本作品将这三类高频动作收敛为**同一套 HTTP API + Web 控制台**，降低「临时脚本 + 口径不一致」带来的返工。

### 1.3 核心能力（与界面 Tab 一致）

1. **案号校验**：对候选案号做规则校验，返回是否合格、归一化信息与规则 ID（例如 `CN-YEAR-SP-001`），非法场景附带原因码与可读说明。
2. **文书抽取**：走**冻结的一条**民事判决书管线；成功则返回法院片段、案号、案由、裁判日期等结构化字段；与管线或标记不匹配时返回明确错误码（例如 `PIPELINE_MISMATCH`），**不以「猜类型」掩盖契约失败**。
3. **合规扫描**：基于本地规则集对输入文本扫描，输出命中列表（含 `ruleId` 与严重级别如 deterministic、suspicious），支持零命中与仅可疑级等演示路径。

### 1.4 产品与工程亮点

- **契约先行**：以 OpenAPI 描述请求、响应与错误语义，前后端与验收对齐。
- **黄金样例回归**：合成 fixture 与可脚本断言场景矩阵（当前矩阵规模 **20** 条 `scenarioId`），覆盖案号分支、文书抽取正负例、合规分级与组合命中；每条规则有稳定 ID，fixture 含请求体与 `*.expected.json`。
- **标准库来源标注（演示）**：案号规则 `CN-*`、合规规则 `R-*`、文书管线 `civil-judgment-v1` 在仓库内以 **synthetic-demo** 形态维护（非全国法院编号全集认证）。
- **非功能口径一致**：单次处理预算与超时语义在 README 与 OpenAPI 中统一声明（见下文「超时与 HTTP 语义」）。
- **技术栈**：后端 Spring Boot 3（Java 17+），前端 Vue 3 + Vite + Element Plus。

### 1.5 API 与文书契约要点（摘录）

三条 MVP 路径的 HTTP 前缀均为 `/api/v1/`：

- 案号校验：`POST /api/v1/case-number/validate`，请求体含候选案号字段（如 `candidate`）。
- 文书抽取：`POST /api/v1/document/extract`；冻结常量包括 `pipelineId=civil-judgment-v1`，`schemaVersion=2026-05-13`，`contentType=text/plain`，`encoding=UTF-8`。成功响应内含 **`extract`** 对象；结构化失败为 **422** 与 **`ExtractErrorResponse`**（如 `PIPELINE_MISMATCH`、`INSUFFICIENT_MARKERS`）。
- 合规扫描：`POST /api/v1/compliance/scan`，响应内含 **`findings`** 数组，项含 `ruleId`、`severity` 等。

### 1.6 超时与 HTTP 语义（与 README 冻结声明一致）

| 项目 | 声明 |
|------|------|
| 服务端单次处理上限 | ≤10s；配置项 `app.processing.timeout-seconds`（默认 `10`） |
| 超时 HTTP 状态码 | **504 Gateway Timeout**（案号、文书抽取、合规三条路径一致） |
| 超时响应体 | **ErrorResponse**：`error=REQUEST_TIMEOUT`，`message` 为可读中文说明 |
| 文书抽取的结构化失败 | **422** + **ExtractErrorResponse**（管线不匹配等），**不**用作一般处理超时响应 |

前端对 `/api` 的请求超时与上述预算对齐（约 10s）。并发设计在配置中有面向约 **20 并发**的容量提示。

### 1.7 适用场景

竞赛演示、课程大作业、法务/合规工具链的原型验证，以及需要**可解释、可回归**规则能力的研发辅助。

### 1.8 数据处理、安全叙事与答辩口径（对外必守）

- 下文 Web 示例正文均为**合成演示**；公开演示**请勿**使用真实当事人或可识别案情。
- 核心三功能**不得要求**将粘贴内容上传到公网服务才能完成；开发与部署应采用本机或内网环境。
- 本 MVP **刻意不包含**：登录与账号体系、运行时依赖 API Key 的云端大模型作为核心业务路径、审计日志产品化；**不得在对外材料中虚假宣传**上述能力。
- 答辩与对外材料须一致表述：本 MVP **无登录、无 API Key、无审计日志**；核心业务路径**不依赖**需密钥的云端大模型；业务数据在**本机/内网**处理；输出为研发辅助与规则命中提示，**不替代**律师、司法机关或合规/安全负责人判断；未经基线或固定任务集的**量化提效百分比**不作为本版验收承诺。
- `fixtures` 内样例为合成/演示用途。若演示中自行粘贴文本，须自行承担隐私与合规风险。

## 二、界面与页面使用说明

应用在本机按仓库说明启动后端与前端后，在浏览器打开开发服务器地址（默认 `http://localhost:5173`）。界面为 **三个 Tab**：**案号校验**、**文书抽取**、**合规扫描**。各 Tab 内输入或粘贴内容后，点击页面上的 **校验**、**抽取** 或 **扫描** 按钮提交。

**数据红线：** 下列示例正文均为仓库合成 fixture，仅用于演示；勿替换为真实案情。

### 2.1 案号校验 — 案例 A（合法，场景 S1-V-001）

1. 打开 Tab「案号校验」。
2. 在输入框粘贴：

```text
（2024）鄂0102民初10001号
```

3. **期望（页面）：** 醒目「校验结果：合格」（绿色）；「归一化」与「规则引用」中含 **`CN-YEAR-SP-001`**。

### 2.2 案号校验 — 案例 B（非法缺年号，场景 S1-I-001）

1. 仍在「案号校验」。
2. 粘贴：

```text
鄂0102民初10001号
```

3. **期望（页面）：** 「校验结果：不合格」（红色）；「原因码」为 **`CN-YEAR-SP-404`**；「说明」可读；「规则引用」列表含对应 ruleId。

### 2.3 文书抽取 — 案例 C（成功，场景 S2-SUCCESS）

1. 打开 Tab「文书抽取」。
2. 将下列正文**全文**复制进正文框（须含「民事判决书」、案号行、「案由：」、日期行等标记）。

```text
湖北省武汉市江岸区人民法院
民事判决书

（2024）鄂0102民初10001号

本案系演示用买卖合同纠纷案件。原告某某贸易公司（占位名称），被告某某商行（占位名称）。

案由：买卖合同纠纷。
经审理查明：双方签订演示购销合同一节，具体内容略。

本院认为（演示）：应当依约另行主张权利。

文书日期：2024-11-01
```

3. **期望（页面）：** 「文书抽取结果：成功」（绿色）；下方结构化字段中 **`extract`** 与黄金样例一致，例如：`courtNameSnippet` →「湖北省武汉市江岸区人民法院」，`caseNumberRaw` →「（2024）鄂0102民初10001号」，`causeSnippet` →「买卖合同纠纷」，`judgementDateISO` → `2024-11-01`。

### 2.4 文书抽取 — 案例 D（管线不匹配，场景 S2-OOR）

1. 仍在「文书抽取」。
2. 将下列正文**全文**粘贴（刑事/决定书风格，不触发民事判决书管线）。

```text
XX市公安局
刑事决定书

犯罪嫌疑单位：演练代号「DEMO-X」一案，根据《刑事诉讼法》第一百三十条（演示占位），决定对涉案财物解除查封。
```

3. **期望（页面）：** 「文书抽取结果：失败（HTTP 422）」（红色）；**`errorCode`** 为 **`PIPELINE_MISMATCH`**；`message` 可读且与契约一致；**不应**出现成功态的法院/案号字段块。

### 2.5 合规扫描 — 案例 E（确定级命中，场景 S3-Scan-HitDeterministic）

1. 打开 Tab「合规扫描」。
2. 粘贴下列全文。

```text
// DEMO ONLY — synthetic digit run resembling ID layout; NOT a real person's number.
const legacyDemoToken = '9876543210123456789';
logDebug(legacyDemoToken);
```

3. **期望（页面）：** 摘要行「合规扫描结果：存在确定级命中（演示）。」（琥珀色）；列表中至少一条 **`severity`** 为 **`deterministic`**，**`ruleId`** 为 **`R-DEMO-ID-LIKE-DIGITS`**。

### 2.6 合规扫描 — 案例 F（零命中，场景 S3-Scan-Clean）

1. 仍在「合规扫描」。
2. 粘贴下列全文。

```text
public final class DemoGreeting {
  public static String hello() {
    return "hello-local-mvp-demo";
  }
}
```

3. **期望（页面）：** 摘要行「合规扫描结果：零命中（findings 为空，演示）。」（绿色）；提示「当前规则集未命中任何条目」，**不**展示命中列表。

### 2.7 合规扫描 — 案例 G（仅可疑级，场景 S3-Scan-Suspicious）

1. 在「合规扫描」粘贴下列全文。

```text
// Wait for upstream to populate 身份证号码字段 in DTO mapper (demo wording only).
dto.setPartyName("SYNTH_PARTY");
```

2. **期望（页面）：** 摘要行「合规扫描结果：存在可疑级命中；无确定级命中（演示）。」（琥珀色）；列表中可见 **`R-DEMO-IDNUM-KEYWORD`** / **`suspicious`**，**不应**出现 **`deterministic`**。

### 2.8 常见界面/API 现象（便于自助排查）

| 现象 | 含义 |
|------|------|
| 案号页面始终「不合格」，但开发者工具里 JSON 已是 `"valid":true` | 多为响应体解析问题；当前前端会对 JSON 字符串体做二次解析并对 `valid` 做布尔归一化。仍异常时需核对后端主 `ObjectMapper` 是否为 JSON 用途。 |
| **504** 且 `error` 为 **REQUEST_TIMEOUT** | 单次处理超过服务端预算（默认 10s）；三路径一致。可缩短输入或稍后重试。 |
| **422**（仅文书抽取） | 正文不符合 `civil-judgment-v1` 管线所需标记，属契约失败，**非**超时。 |
| **`findings: []`** | 当前规则集无命中（清洁样例）；**不是**接口失败。 |

## 三、产品规划

以下规划在**不违背当前契约冻结与 MVP 不做清单**的前提下描述演进方向；任何范围变更须先评估对 OpenAPI、fixture 与黄金场景矩阵的影响。

### 3.1 近期（巩固 MVP）

- **规则与标准库**：在 synthetic-demo 标注策略下，扩充案号边界用例与合规规则 ID，保持「每条规则可追溯至 fixture」。
- **可观测性（研发侧）**：结构化日志、基础指标（请求量、422/504 比例）；**不**等同于产品化「审计追踪」（当前仍不承诺谁在何时处理了哪条业务数据）。
- **文档与演示**：与推广版使用说明、答辩一页纸保持同步；若需要英文对外材料，单独撰写，不改动契约真源。

### 3.2 中期（能力扩展，仍优先离线、可解释）

- **文书管线**：在 OpenAPI 与黄金矩阵**显式版本化**后，审慎增加第二条冻结管线（例如裁定书、调解书），每条管线独立 `pipelineId` 与 `schemaVersion`，失败语义保持「契约失败而非模型猜测」。
- **合规规则集**：分级策略、规则包切换（如「演示包 / 内训包」）、导出命中报告（JSON 或 Markdown）。
- **部署形态**：Docker Compose 一键起停；可选仅 API 模式供 CI 与其他服务调用。

### 3.3 长期（与主需求愿景区分后的可选方向）

长期愿景文档中的能力若与当前 MVP 冲突，以补充说明类文档与验收文档中的冻结范围为准。可选方向包括（均需单独立项与合规评审）：

- **账号与租户**：多用户、RBAC、API Key（仅当明确脱离「匿名本机演示」定位时）。
- **可选外接能力**：知识库、自然语言生成代码等**不得**静默替换当前三条核心路径的离线契约；若引入大模型，须在架构上隔离为**可选插件**并标明数据出境与留痕责任。
- **效果度量**：任何「提效百分之 X」类表述须绑定基线任务集与打分表后再对外宣传。

### 3.4 明确不在本规划内默认承诺的事项

**全国案号全集司法认证**、替代专业法律意见、未经验证的量化业务收益、运行时**强制**依赖公网大模型完成案号、文书抽取或合规扫描核心链路。
